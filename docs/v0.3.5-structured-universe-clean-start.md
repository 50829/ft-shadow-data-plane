# v0.3.5 结构化 universe clean start

## 唯一合同

v0.3.5 删除旧单整数 generation 合同和所有兼容、adapter、迁移锚点。collector 与 107 central
只实现一个 `UniverseDecision`：

```json
{
  "core_generation": 6,
  "candidate_revision": 2,
  "decision_sequence": 8,
  "universe_version": "6.2",
  "universe_hash": "439258f232c9cd174bc1a3900ea3802c3bc3f3e78381be620732dbd3de96a94c"
}
```

`6.2` 不是浮点数。50 个 core 变化时 `core_generation += 1` 且 revision 归零；仅 boundary/probe
变化时 revision 加一；成员完全不变不产生 decision。`decision_sequence` 为实际 decision 提供严格
全序，`universe_hash` 绑定精确且有角色的 50/5/5。

手工 candidate override 不允许指定版本号；Vultr 根据 active 分配下一 revision 和 sequence。

## 新正式起点

clean start 直接冻结此前 selector 已批准的 `6.2` 60 币，不读取旧 active/pending。机器可读证据为
[formal-universe-6.2-evidence.json](formal-universe-6.2-evidence.json)，文件 SHA-256 是：

```text
d1eb8664c9636c78627e9768b4c874594bd48a31f3fdc115476788368207abf0
```

该文件保留 selector 观察时间、5 个原始 source hash、角色列表和
`439258f232c9cd174bc1a3900ea3802c3bc3f3e78381be620732dbd3de96a94c`。collector 启动时仍会用
新的双重 exchangeInfo、14 个完整 UTC 日、bookTicker 与 depth 证据重新验证全部 60 币；任一角色
不满足正式门槛就 fail closed，不写 formal start。

## 保留旧数据但隔离合同

旧数据不删除，也不由新代码解析：

- 先让 107 拉完 Vultr ready，确认 `failures=0`；
- 停止 107 cron，并等待现有 pull 退出；
- 把旧 `data/raw`、`data/derived` 和 runtime 元数据原地移动到带时间戳的
  `data/archive/pre-v0.3.5-*`；同一文件系统 rename 不复制约 91.4 GiB 数据；
- 把 Vultr 旧 control/evidence/gap 打包保存到同一 107 archive；
- 新版本只使用新建的空 `data/raw`、`data/derived` 与 runtime；
- 旧 archive 改为只读，任何离线旧版分析都必须显式指向 archive，不得混入新数据日目录。

Vultr 1C1G/25GB 不长期保留第二份 ready；只有在 107 已校验落盘并完成 archive 后才重置旧 spool。

## Storage recovery 修复

磁盘硬限制解除后，如果 source group 在 600 秒内未达到完整 readiness，v0.3.4 会让超时逃出 storage
monitor 并终止 collector。v0.3.5 保持原 `STORAGE_EXHAUSTED_GAP` OPEN，停止并清理半启动 source
group，下一轮重新尝试；只有全源 ready 后才关闭 gap。spool、writer、gap journal 和日封存等真正的
完整性异常仍向上抛出，不会被恢复分支吞掉。

## 上线验收

最终部署使用包含 sealed-day pull 性能修复的同一个 v0.3.6 release；结构化 universe 合同和冻结名单
仍是 v0.3.5 定义的内容。Vultr 启动后核对：

```bash
sudo jq '{core_generation,candidate_revision,decision_sequence,universe_version,
          universe_hash,core,boundary,probe}' \
  /srv/ft-data-rsync/control/universe/active.json
sudo test ! -e /srv/ft-data-rsync/control/universe/pending.json
sudo find /srv/ft-data-rsync/control/open-gaps -maxdepth 1 -type f -print
```

预期 active 为 `6.2 / sequence 8`、恰好 50/5/5，formal-start 属于新实验
`formal-60-v3-2026-08-22`。新 raw 出现后恢复 107 cron，至少连续两次 `pull complete ... failures=0`，
并确认 ACK 使 Vultr ready 正常回收。
